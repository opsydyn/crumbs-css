`@opsydyn/crumbs-css` is a React Native subset of vanilla-extract-shaped authoring. It is not a browser CSS runtime.

## Expo SDK compatibility

Crumbs `1.2.0` is published on npm as `latest` and on GitHub. The [release record](https://github.com/opsydyn/crumbs-css/blob/main/docs/releases/1.2.0.md) identifies the verified artifact and explicitly accepted compiler baseline. Crumbs `1.2.0` adds Expo SDK 58 / React Native 0.88, retaining SDK 56 / RN 0.85 and SDK 57 / RN 0.86. Earlier `1.1.1` covers SDK 56/57 only. The current internal apps use Expo 58.0.14, React/DOM 19.3.1 and RN 0.88.0. The retained installed profiles use Expo 56.0.4/RN 0.85.3 and Expo 57.0.27/RN 0.86.3 with React 19.2.8. Strict npm resolution, packed types, motion contracts and iOS/Android/web exports are checked without peer overrides.

Native peers are `>=0.85 <0.87 || >=0.88 <0.89`; RN 0.87 remains unqualified. Crumbs tooling keeps Node >=22.0.0. SDK 56/57 tooling needs `>=22.13.0`; SDK 58 requires `^22.13.0 || ^24.3.0 || ^26.0.0 || >=27.0.0`. Check [release status](https://github.com/opsydyn/crumbs-css/blob/main/docs/releases/1.2.0.md) for publication separately from source qualification.

Babel remains the default. SDK 58's optional Expo Rust worker is qualified through actual eligible-file completion events, with explicit codegen/Animated/Worklets and custom-parser Babel fallbacks. See [consumer worker setup](/crumbs-css/how-to/configure-metro/#opt-into-expos-rust-transformer-sdk-58) and [internal app checks](/crumbs-css/how-to/use-storybook-and-expo-dev-client/) and the [source/native packet](https://github.com/opsydyn/crumbs-css/tree/main/docs/evidence/2026-10-16-m1-10b-expo58-apps). Both apps have owned iOS/Android development-client interaction evidence under both workers. Physical devices, spoken readers, iOS 27/DeviceHub behavior and release FPS remain deferred. This interoperability work makes no throughput claim. The accepted [M10.5 compiler-baseline amendment](https://github.com/opsydyn/crumbs-css/blob/main/docs/evidence/2026-10-18-m10-5-v12-rebaseline/README.md) governs the 1.2.0 release; earlier version-specific exceptions remain historical.

## Supported

- `style`
- composition through `style([base, extra])`
- `styleVariants`
- `recipe`
- `createRecipeResolver`
- `createThemeContract` and `createTheme`
- typed native helpers
- runtime theme token resolution

## Dropped or unsupported

- vendor-prefixed properties
- browser CSS variables such as `var(--brand)`
- CSS selectors and pseudo classes
- `globalStyle`
- nested selectors and selector lists
- `@media`
- `@keyframes`
- browser-only at-rules such as `@supports`, `@font-face`, and `@layer`

## DTCG import tooling (M9.6)

`@opsydyn/crumbs-css/tooling/dtcg` provides a synchronous, opt-in import API for
the documented 2025.10 Format/Color/Resolver profile. It accepts only explicit
in-memory documents and one manifest contract identity, and returns a v1 theme
payload with provenance or stable diagnostics. Effect 4 is bundled inside this
tooling artifact; applications do not need an Effect import or runner. See the
[DTCG conversion matrix and workflow](/crumbs-css/how-to/import-dtcg-tokens/).

M9.6 qualification covers checked-in source fixtures and generated host
workloads. A 1,000-token workload completed on the recorded Bun host; 10,000
and 50,000-token workloads stopped at the 100,000 JSON-node resource guard.
Those are tooling-side observations, not runtime or device performance
measurements. This historical M9.6 packet did not qualify publication or native acceptance.
Later native evidence belongs to its own exact feature/artifact receipts;
physical-device and spoken-reader acceptance remain deferred.

## Release lifecycle and deprecations

The stable v1 surface is published on npm and GitHub. Version `1.1.0` adds qualified Expo SDK 57 / React Native 0.86 support while retaining SDK 56 / React Native 0.85. Its runtime and compiler JavaScript match verified npm `1.0.1`. The [1.1.0 publication disposition](https://github.com/opsydyn/crumbs-css/blob/main/docs/releases/1.1.0.md) retains the recorded warm-transform failure and unchanged generic future-release limits.
The [v1-only release disposition](https://github.com/opsydyn/crumbs-css/blob/main/docs/releases/1.0.0.md) retains the recorded warm and incremental failures and unchanged future-release gates. The [2026-10-18 amendment](https://github.com/opsydyn/crumbs-css/blob/main/docs/evidence/2026-10-18-m10-5-v12-rebaseline/README.md) subsequently adopts the measured v1.2.0 cold, warm and incremental compiler baselines, retaining their regression percentages and all other checks. Public APIs and published artifact
formats follow SemVer; stable removals require a documented replacement, migration
guidance and at least one minor release of deprecation before a major release.
The earlier alpha release policy and retained qualification tables are historical
records of those exact artifacts. Promotion to v1 removes no existing APIs.

Release-please creates GitHub releases and tags but never publishes to npm.
Publishing is a separate manual workflow gated on a completed, version-matched
GitHub Release. See the [full package compatibility and release policy](https://github.com/opsydyn/crumbs-css/blob/main/packages/css/COMPATIBILITY.md).
