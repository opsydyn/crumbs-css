## Entrypoints

### `@opsydyn/crumbs-css`

Use the package root for:

- `NativeStylesDiagnosticCode`
- `withNativeStyles`

### `@opsydyn/crumbs-css/style`

Use this entrypoint in `.css.ts` authoring modules for:

- `style`
- `styleVariants`
- `recipe`
- `componentRecipe`, `componentRecipeFromRecipe`, and `extendComponentRecipe`
- `defineProperties`, `createSprinkles`, and `createSprinklesLookupPlan` for finite, primitive-scoped utility scales
- `createThemeContract`
- `createTheme`
- `viewStyle`
- `textStyle`
- `imageStyle`
- type exports such as `NativeRecipeProps`, `NativeComponentRecipeProps`, `NativeComponentPublicProps`, and `NativeComponentResolvedStyles`

### Typed component recipes

`componentRecipe` declares a component's named view, text, and image style
slots. Each slot checks style properties against its React Native primitive,
while every slot shares the component's single variant selection.

```ts
// button.css.ts
import {
  componentRecipe,
  type NativeComponentRecipeProps,
} from "@opsydyn/crumbs-css/style"

export const button = componentRecipe({
  slots: { root: "view", label: "text", icon: "image" } as const,
  base: {
    root: { paddingHorizontal: 12 },
    label: { fontWeight: "700" },
    icon: { resizeMode: "contain" },
  },
  variants: {
    status: {
      ready: { root: { opacity: 1 } },
      loading: { root: { opacity: 0.7 } },
    },
    busy: {
      false: { root: { opacity: 1 } },
      true: { root: { opacity: 0.8 } },
    },
    tone: {
      primary: {
        root: { backgroundColor: "#1648d8" },
        label: { color: "white" },
      },
      quiet: {
        root: { backgroundColor: "transparent" },
        label: { color: "#202020" },
      },
    },
  },
  defaultVariants: { status: "ready", busy: false, tone: "primary" },
  stateVariants: {
    status: {
      ready: { busy: [false], tone: ["primary", "quiet"] },
      loading: { busy: [true], tone: ["primary"] },
    },
  },
}, "button")

export type ButtonSelection = NativeComponentRecipeProps<typeof button>

const readyQuiet: ButtonSelection = { tone: "quiet" }
const loadingPrimary: ButtonSelection = {
  status: "loading",
  busy: true,
  tone: "primary",
}
```

`stateVariants` adds one discriminator over the recipe's existing variant
axes. Its cases must cover every value of that discriminator exactly once;
each case may constrain other axes to non-empty lists of values declared by
those variants. These constraints add no style branches: the ordinary
`variants` map continues to own the styles.

The type `ButtonSelection` reflects those case constraints. For example,
`readyQuiet` uses the defaults `status: "ready"` and `busy: false`, so the
quiet tone is permitted. `loadingPrimary` explicitly selects the required
loading values. At runtime Crumbs merges `defaultVariants` with the supplied
selection before checking the active case. If a selection violates that
case's constraints, the resolver returns only base styles for every slot,
skips variant and compound styles, and reports the invalid state in
development. This fail-closed behavior also covers untyped callers and
runtime data; invalid independent variant values outside a state constraint
retain their existing warn-and-skip behavior.

Newly authored component recipes emit descriptor version 2 with the finite
state map. Runtime readers continue to accept version 1 descriptors with
their previous unconstrained behavior, as well as version 2; unsupported
descriptor versions fail closed. The resolver stores authored variant
branches and state cases, then checks only the selected case. It does not
materialize the Cartesian product of all variant values.

Resolve tokenized descriptors through the theme hook before creating a
resolver. The same selection is applied to all slots; omitted slot branches
resolve to empty arrays. Results append base styles, matching variants in
authored order, then matching compounds in authored order.

```tsx
import { useMemo } from "react"
import type { ImageStyle, TextStyle, ViewStyle } from "react-native"
import { createComponentRecipeResolver } from "@opsydyn/crumbs-css/theme/recipes"
import { useThemedStyles } from "@opsydyn/crumbs-css/theme/core"
import { button, type ButtonSelection } from "./button.css"

function useButtonStyles(tone: NonNullable<ButtonSelection["tone"]>) {
  const themed = useThemedStyles({ button })
  const resolve = useMemo(
    () => createComponentRecipeResolver(themed.button),
    [themed.button],
  )
  const selection: ButtonSelection = { tone }
  const styles = resolve(selection)

  const rootStyles: ReadonlyArray<ViewStyle> = styles.root
  const labelStyles: ReadonlyArray<TextStyle> = styles.label
  const iconStyles: ReadonlyArray<ImageStyle> = styles.icon
  return { rootStyles, labelStyles, iconStyles }
}
```

`createComponentRecipeResolver(recipe, { cacheSize })` builds one plan and one
resolver-local least-recently-used cache for every slot. The default cache is
32 selections, bounded to `0..1024`; `0` disables retention. It exposes
`getCacheStats()`, `clearCache()`, and `dispose()`. Invalid runtime variant
values are warned about and skipped. `componentRecipeFromRecipe(recipe,
{ slot })` wraps a legacy recipe in one named **view** slot; it preserves that
recipe's variant selection and cannot relabel the style as text or image.

### Public tokens, component contracts, and extensions

Token visibility is declared by the token contract that owns each path. An
omitted `visibility` option keeps identified tokens public for compatibility;
when a list is supplied, every other definition token is private. Aliases
inherit visibility from their terminal definition.

```ts
import { createTokenContract, defineAlias, defineToken } from "@opsydyn/crumbs-css/tokens"

export const tokens = createTokenContract({
  color: {
    accent: defineToken("color"),
    implementation: defineToken("color"),
  },
  semantic: {
    foreground: defineAlias("color.accent"),
  },
}, {
  identity: { owner: "@acme/tokens", name: "brand", version: 1 },
  visibility: { public: [["color", "accent"]] },
})
```

The public path set participates in the stable contract identity. Keep it
unchanged for that identity or increment its version when the published
surface changes. Visibility is compatibility metadata, not secrecy or an
authorization boundary: runtime values and descriptors are inspectable.

A component contract publishes the slots and variant values that consumers
may select, and opts in to each extension operation. Omitted extension points
are sealed. The owner keeps a richer selection type than consumers receive:

```ts
import {
  componentRecipe,
  extendComponentRecipe,
  type NativeComponentPublicProps,
  type NativeComponentRecipeProps,
} from "@opsydyn/crumbs-css/style"
import { tokens } from "./tokens"

export const button = componentRecipe({
  contract: {
    identity: { owner: "@acme/ui", name: "Button", version: 1 },
    public: {
      slots: ["root", "label"],
      variants: { tone: ["primary", "quiet"] },
    },
    extensionPoints: {
      defaults: ["tone"],
      variantValues: ["tone"],
      compoundVariants: true,
      slotStyles: ["root"],
    },
  },
  slots: { root: "view", label: "text", internalIcon: "image" } as const,
  variants: {
    tone: {
      primary: { root: { backgroundColor: tokens.color.accent } },
      quiet: { root: { opacity: 0.8 } },
      dangerInternal: { root: { opacity: 0.4 } },
    },
    density: { compact: { internalIcon: { width: 12 } } },
  },
  defaultVariants: { tone: "primary", density: "compact" },
}, "button")

type OwnerSelection = NativeComponentRecipeProps<typeof button>
type ConsumerSelection = NativeComponentPublicProps<typeof button>
const ownerSelection: OwnerSelection = { density: "compact", tone: "dangerInternal" }
const consumerSelection: ConsumerSelection = { tone: "quiet" }

export const brandedButton = extendComponentRecipe(button, {
  identity: { owner: "@acme/brand", name: "BrandedButton", version: 1 },
  defaultVariants: { tone: "brand" },
  variants: { tone: { brand: { root: { backgroundColor: tokens.semantic.foreground } } } },
  slotOverrides: { root: { borderRadius: 12 } },
})

type BrandedSelection = NativeComponentPublicProps<typeof brandedButton>
const brandedSelection: BrandedSelection = { tone: "brand" }
```

The owner can select private implementation variants through
`NativeComponentRecipeProps`. `NativeComponentPublicProps` contains only the
contract's public axes and values, plus values added through the extension
chain. Extension defaults, new values, compounds, and slot styles each require
the matching `extensionPoints` permission; extension identities form one
validated base-to-leaf chain. Extension resolvers reject explicit selections
of private owner values before cache lookup. Unknown public values retain the
resolver's warn-and-skip behavior. TypeScript checks inferred extension configs
against the same permissions, including mixed and union-shaped maps, compound
records, and identity keys; runtime validation also protects JavaScript and
widened inputs.

Defaults merge from owner to extensions in base-to-leaf order, then caller
selection wins:

```ts
const selected = { ...ownerDefaults, ...baseExtensionDefaults, ...leafExtensionDefaults, ...caller }
```

For a valid v3 selection, every slot receives styles in this order:

1. Owner base slot styles.
2. Ordinary variant branches in the owner's authored axis order, including
   permitted extension values on those axes.
3. The state-discriminator branch, after ordinary variants.
4. Matching compounds: owner first, then each extension base-to-leaf.
5. Permitted slot overrides, extension base-to-leaf.

If a state case rejects the normalized selection, resolution returns only the
owner's base slot styles and skips variants, compounds, and overrides. This
behavior applies to typed and untyped callers. Existing v1 descriptors retain
their unconstrained behavior, v2 descriptors retain state constraints, and
contract-bearing recipes use v3. Unsupported future versions fail closed.

`createComponentRecipeResolver` validates the complete extension chain and
builds its plan once. It stores authored branches and constraints rather than
materializing every variant combination; selection caching remains bounded and
resolver-local. Manifest generation, policy checks, and automated public
surface impact tooling belong to M9 and are not part of the runtime contract
API.

### Native sprinkles

Define each finite scale against the primitive kinds that may consume it. The
property value is checked against the React Native property type, and branded
domain tokens retain their colour, length, opacity, or enum boundary.

```ts
import { createSprinkles, defineProperties } from "@opsydyn/crumbs-css/style"

const viewProperties = defineProperties({
  primitives: ["view"] as const,
  properties: {
    paddingLeft: { sm: 8, lg: 24 },
    paddingRight: { sm: 8, lg: 24 },
    backgroundColor: { canvas: "#0a0a0a" },
  },
  shorthands: {
    px: ["paddingLeft", "paddingRight"] as const,
  },
})

export const sprinkles = createSprinkles(viewProperties)
export const card = sprinkles({ px: "sm", paddingLeft: "lg" })
```

Selection keys are resolved in authored object order. Here `px` first assigns
both physical sides, then `paddingLeft: "lg"` replaces only the left side;
`paddingRight` remains `8`. `false`, `null`, and `undefined` omit a selection,
and an unknown scale or shorthand target fails before a class is emitted.

Utility outputs compose directly with Crumbs helpers and recipe branches. The
mapper overload follows vanilla-extract's data-first shape while retaining the
native result type:

```ts
const spacing = { compact: "sm", roomy: "lg" } as const

export const spacingStates = styleVariants(spacing, (scale, state) => {
  return sprinkles({ px: scale })
})

export const card = recipe({
  base: sprinkles({ px: "sm" }),
  variants: {
    density: {
      compact: spacingStates.compact,
      roomy: spacingStates.roomy,
    },
  },
})
```

The mapper receives the finite value and its key. Static utility classes keep
their primitive scope and token payload through composition, mapped variants,
recipe bases, branches, and compound styles.

For values chosen from component state, export a generated lookup plan from the
authored module. It contains one compiled reference per property and scale, so
runtime selection does not expand a Cartesian product of all combinations:

```ts
// spacing.css.ts
import { createSprinklesLookupPlan } from "@opsydyn/crumbs-css/style"

export const sprinklesPlan = createSprinklesLookupPlan(viewProperties, "spacing")
```

Resolve the plan through the normal theme path, then create a bounded runtime
resolver. Selection order remains authored order, including shorthand targets;
the resolver returns a readonly array suitable for a React Native `style` prop.

```tsx
import { createSprinklesResolver } from "@opsydyn/crumbs-css/theme/sprinkles"
import { useThemedStyles } from "@opsydyn/crumbs-css/theme/core"
import { useMemo } from "react"
import { View } from "react-native"
import * as s from "./spacing.css"

export function Card({ compact }: { compact: boolean }) {
  const themed = useThemedStyles(s)
  const resolve = useMemo(
    () => createSprinklesResolver(themed.sprinklesPlan),
    [themed.sprinklesPlan],
  )
  return <View style={resolve({ px: compact ? "sm" : "lg" })} />
}
```

`createSprinklesResolver(plan, { cacheSize })` defaults to a resolver-local
least-recently-used cache of 32 selections, bounded to `0..1024`; `0` disables
retention. It exposes `getCacheStats()`, `clearCache()`, and `dispose()` just
like the recipe resolver. `createSprinkles` remains the authored static path;
the `NativeSprinklesLookupPlan` and `NativeSprinklesResolver` types make the
static/runtime boundary explicit.

### `@opsydyn/crumbs-css/theme/token`

Use this additive path for flat native style maps whose token references should
retain the domain and value type from `createTokenContract`:

```tsx
import { createTokenStyles, themeToken, ThemeProvider, useTokenStyles } from "@opsydyn/crumbs-css/theme/token"
import { createTokenContract, createTokenTheme, defineToken } from "@opsydyn/crumbs-css/tokens"
import type { ViewStyle } from "react-native"
import { View } from "react-native"

const vars = createTokenContract({
  color: { surface: defineToken("color") },
  space: { card: defineToken("length") },
})
const light = createTokenTheme(vars, { color: { surface: "#ffffff" }, space: { card: 16 } })
const styles = createTokenStyles<ViewStyle>()({
  card: {
    backgroundColor: themeToken(vars.color.surface),
    padding: themeToken(vars.space.card),
  },
})

function Card() {
  const themed = useTokenStyles(styles)
  return <View style={themed.card} />
}

export function App() {
  return <ThemeProvider theme={light}><Card /></ThemeProvider>
}
```

`themeToken` accepts only a domain-branded reference from `createTokenContract`.
`createTokenStyles<ViewStyle | TextStyle | ImageStyle>()` checks that each token
domain and its contract-derived value fit the selected native property. Use
`resolveTokenStyles(styles, theme)` for non-React resolution. The supported
shape is a flat record of style names to primitive native properties; arrays,
nested style values, conditions, recipes, component slots, and extensions stay
on the existing authoring/runtime paths.

This path is opt-in and additive. Its provider shares the canonical theme store
with the existing theme entries. It does not replace `theme/core`, change an
existing import, or promise a smaller application bundle, startup time, native
frame time, or memory use. Use `theme/core` for the general style-resolution
surface and `theme/token` when contract-derived token/property compatibility is
the reason to choose a narrower API.

### Focused theme feature paths

Use these additive paths when a package or application module needs one theme
feature family without importing the wider compatibility API:

| Path | API family |
| --- | --- |
| `@opsydyn/crumbs-css/theme/conditions` | Native condition snapshots, normalization, branch tracing, store and React subscription hook. |
| `@opsydyn/crumbs-css/theme/expressions` | Typed expression data, constructors, dependency inspection, evaluation, tracing and folding. |
| `@opsydyn/crumbs-css/theme/recipes` | Recipe and component-recipe plan constructors, resolvers and cache controls. |
| `@opsydyn/crumbs-css/theme/sprinkles` | Bounded runtime Sprinkles resolver and lookup/resolution plan types. |

The paths are additive and share canonical bindings with `theme`; existing
imports remain supported. Conditions has a React peer dependency for its hook,
while expressions, recipes and Sprinkles have no runtime external dependency.
Choose a focused path for a narrower public dependency boundary. It does not by
itself guarantee a smaller application bundle: bundler tree-shaking, reachable
imports and the consuming app determine the result. Check the production
consumer bundle and source maps before claiming a size improvement.

### `@opsydyn/crumbs-css/tokens`

Use this runtime-safe entrypoint for domain-aware token contracts and theme
snapshots:

- `createTokenContract`
- `createTokenTheme`
- `createTokenThemeFromExternalPayload`
- `applyTokenThemePatch`
- `createTokenThemeScope`
- `alias` and `defineAlias`
- `defineToken` and `token`

Its contract/theme construction graph contains only plain runtime data and
validation helpers. `@opsydyn/crumbs-css/tokens/schema` and
`@opsydyn/crumbs-css/tokens/optic` are explicit advanced boundaries for Effect
Schema decoding and Optic-based updates.

`createRecipeResolver(recipe, { cacheSize })` precomputes the recipe selection
plan and returns a callable resolver with `getCacheStats()`, `clearCache()` and
`dispose()` controls. The cache is resolver-local, least-recently-used and
bounded to `0..1024` entries; the default is `32` and `0` disables retention.

`useThemeSelector(selector)` subscribes to the selected value of the nearest
theme snapshot. Selectors should return a stable reference for unchanged
input; primitives are the simplest choice. The hook is intended for focused
token or derived-style reads when a component should not observe unrelated
theme changes.

### `@opsydyn/crumbs-css/tooling/dtcg`

Use this synchronous, opt-in tooling entrypoint to import an explicitly
selected DTCG Format/Resolver snapshot into a manifest-backed Crumbs theme
payload. It accepts an in-memory absolute-URI document map, a selected
manifest contract identity, optional modifier selections, and an explicit
`remBasePx` when the selected sources contain `rem` dimensions. It returns the
version-1 theme payload with a provenance sidecar or stable diagnostics; it
does not read files or fetch URLs.

The supported DTCG profile and native conversion matrix are deliberately
narrow. Effect 4 is bundled inside this tooling boundary; consumers do not add
an Effect dependency or use an Effect runner. The adapter is not re-exported
from ordinary runtime entrypoints. See the [DTCG import guide](../how-to/import-dtcg-tokens/).

### `@opsydyn/crumbs-css/tooling/ownership`

Use this local-only tooling entrypoint to decode a versioned ownership map,
annotate supported reports against explicitly supplied manifests, and encode a
canonical owned-report envelope. It exports `decodeDesignSystemOwnership`,
`annotateDesignSystemReport`, and `encodeCanonicalOwnedReport`, together with
plain ownership, attribution, and report types. The report adapters cover
compatibility, policy, source migration, style explanation, and DTCG import
results. Assignments use exact stable manifest IDs; names and paths are not
identity fallbacks. Effect 4 Schema is bundled behind this entrypoint, so
consumers do not add an Effect dependency. See the
[local ownership guide](../how-to/annotate-design-system-ownership/).
