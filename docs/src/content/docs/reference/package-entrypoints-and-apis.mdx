## Entrypoints

### `@opsydyn/crumbs-css`

Use the package root for:

- `NativeStylesDiagnosticCode`
- `withNativeStyles`

### `@opsydyn/crumbs-css/style`

Use this entrypoint in `.css.ts` authoring modules for:

- `style`
- `styleVariants`
- `recipe`
- `componentRecipe` and `componentRecipeFromRecipe`
- `defineProperties`, `createSprinkles`, and `createSprinklesLookupPlan` for finite, primitive-scoped utility scales
- `createThemeContract`
- `createTheme`
- `viewStyle`
- `textStyle`
- `imageStyle`
- type exports such as `NativeRecipeProps`, `NativeComponentRecipeProps`, and `NativeComponentResolvedStyles`

### Typed component recipes

`componentRecipe` declares a component's named view, text, and image style
slots. Each slot checks style properties against its React Native primitive,
while every slot shares the component's single variant selection.

```ts
// button.css.ts
import {
  componentRecipe,
  type NativeComponentRecipeProps,
} from "@opsydyn/crumbs-css/style"

export const button = componentRecipe({
  slots: { root: "view", label: "text", icon: "image" } as const,
  base: {
    root: { paddingHorizontal: 12 },
    label: { fontWeight: "700" },
    icon: { resizeMode: "contain" },
  },
  variants: {
    tone: {
      primary: {
        root: { backgroundColor: "#1648d8" },
        label: { color: "white" },
      },
      quiet: {
        root: { backgroundColor: "transparent" },
        label: { color: "#202020" },
      },
    },
  },
  defaultVariants: { tone: "primary" },
}, "button")

export type ButtonSelection = NativeComponentRecipeProps<typeof button>
```

Resolve tokenized descriptors through the theme hook before creating a
resolver. The same selection is applied to all slots; omitted slot branches
resolve to empty arrays. Results append base styles, matching variants in
authored order, then matching compounds in authored order.

```tsx
import { useMemo } from "react"
import type { ImageStyle, TextStyle, ViewStyle } from "react-native"
import { createComponentRecipeResolver } from "@opsydyn/crumbs-css/theme"
import { useThemedStyles } from "@opsydyn/crumbs-css/theme/core"
import { button, type ButtonSelection } from "./button.css"

function useButtonStyles(tone: NonNullable<ButtonSelection["tone"]>) {
  const themed = useThemedStyles({ button })
  const resolve = useMemo(
    () => createComponentRecipeResolver(themed.button),
    [themed.button],
  )
  const selection: ButtonSelection = { tone }
  const styles = resolve(selection)

  const rootStyles: ReadonlyArray<ViewStyle> = styles.root
  const labelStyles: ReadonlyArray<TextStyle> = styles.label
  const iconStyles: ReadonlyArray<ImageStyle> = styles.icon
  return { rootStyles, labelStyles, iconStyles }
}
```

`createComponentRecipeResolver(recipe, { cacheSize })` builds one plan and one
resolver-local least-recently-used cache for every slot. The default cache is
32 selections, bounded to `0..1024`; `0` disables retention. It exposes
`getCacheStats()`, `clearCache()`, and `dispose()`. Invalid runtime variant
values are warned about and skipped. `componentRecipeFromRecipe(recipe,
{ slot })` wraps a legacy recipe in one named **view** slot; it preserves that
recipe's variant selection and cannot relabel the style as text or image.

### Native sprinkles

Define each finite scale against the primitive kinds that may consume it. The
property value is checked against the React Native property type, and branded
domain tokens retain their colour, length, opacity, or enum boundary.

```ts
import { createSprinkles, defineProperties } from "@opsydyn/crumbs-css/style"

const viewProperties = defineProperties({
  primitives: ["view"] as const,
  properties: {
    paddingLeft: { sm: 8, lg: 24 },
    paddingRight: { sm: 8, lg: 24 },
    backgroundColor: { canvas: "#0a0a0a" },
  },
  shorthands: {
    px: ["paddingLeft", "paddingRight"] as const,
  },
})

export const sprinkles = createSprinkles(viewProperties)
export const card = sprinkles({ px: "sm", paddingLeft: "lg" })
```

Selection keys are resolved in authored object order. Here `px` first assigns
both physical sides, then `paddingLeft: "lg"` replaces only the left side;
`paddingRight` remains `8`. `false`, `null`, and `undefined` omit a selection,
and an unknown scale or shorthand target fails before a class is emitted.

Utility outputs compose directly with Crumbs helpers and recipe branches. The
mapper overload follows vanilla-extract's data-first shape while retaining the
native result type:

```ts
const spacing = { compact: "sm", roomy: "lg" } as const

export const spacingStates = styleVariants(spacing, (scale, state) => {
  return sprinkles({ px: scale })
})

export const card = recipe({
  base: sprinkles({ px: "sm" }),
  variants: {
    density: {
      compact: spacingStates.compact,
      roomy: spacingStates.roomy,
    },
  },
})
```

The mapper receives the finite value and its key. Static utility classes keep
their primitive scope and token payload through composition, mapped variants,
recipe bases, branches, and compound styles.

For values chosen from component state, export a generated lookup plan from the
authored module. It contains one compiled reference per property and scale, so
runtime selection does not expand a Cartesian product of all combinations:

```ts
// spacing.css.ts
import { createSprinklesLookupPlan } from "@opsydyn/crumbs-css/style"

export const sprinklesPlan = createSprinklesLookupPlan(viewProperties, "spacing")
```

Resolve the plan through the normal theme path, then create a bounded runtime
resolver. Selection order remains authored order, including shorthand targets;
the resolver returns a readonly array suitable for a React Native `style` prop.

```tsx
import { createSprinklesResolver } from "@opsydyn/crumbs-css/theme"
import { useThemedStyles } from "@opsydyn/crumbs-css/theme/core"
import { useMemo } from "react"
import { View } from "react-native"
import * as s from "./spacing.css"

export function Card({ compact }: { compact: boolean }) {
  const themed = useThemedStyles(s)
  const resolve = useMemo(
    () => createSprinklesResolver(themed.sprinklesPlan),
    [themed.sprinklesPlan],
  )
  return <View style={resolve({ px: compact ? "sm" : "lg" })} />
}
```

`createSprinklesResolver(plan, { cacheSize })` defaults to a resolver-local
least-recently-used cache of 32 selections, bounded to `0..1024`; `0` disables
retention. It exposes `getCacheStats()`, `clearCache()`, and `dispose()` just
like the recipe resolver. `createSprinkles` remains the authored static path;
the `NativeSprinklesLookupPlan` and `NativeSprinklesResolver` types make the
static/runtime boundary explicit.

### `@opsydyn/crumbs-css/theme`

Use this compatibility entrypoint in runtime/component code when you need the
advanced theme APIs:

- `createThemeDependencyPlan`
- `createThemeDependencyResolver`
- `resolveRecipeStyle`
- `createRecipeResolver`
- `resolveComponentRecipeStyles`
- `createComponentRecipeResolver`
- `createSprinklesResolver`
- `TokenThemeProvider`
- `TokenThemeScopeProvider`
- `useTokenTheme`

### `@opsydyn/crumbs-css/theme/core`

Use this lean entrypoint for common provider, hook and token-resolution code:

- `ThemeProvider`
- `useTheme`
- `useThemeSelector`
- `useThemedStyle`
- `useThemedStyles`
- `resolveThemeTokens`
- `resolveThemeStyles`
- `createThemeTokenReference`
- `isThemeTokenReference`

It is emitted as an independent graph so consumers that do not need scopes,
dependency plans or recipe controls do not load those implementations. Both
theme entrypoints retain a React-only external runtime dependency boundary.

### `@opsydyn/crumbs-css/tokens`

Use this runtime-safe entrypoint for domain-aware token contracts and theme
snapshots:

- `createTokenContract`
- `createTokenTheme`
- `createTokenThemeFromExternalPayload`
- `applyTokenThemePatch`
- `createTokenThemeScope`
- `alias` and `defineAlias`
- `defineToken` and `token`

Its contract/theme construction graph contains only plain runtime data and
validation helpers. `@opsydyn/crumbs-css/tokens/schema` and
`@opsydyn/crumbs-css/tokens/optic` are explicit advanced boundaries for Effect
Schema decoding and Optic-based updates.

`createRecipeResolver(recipe, { cacheSize })` precomputes the recipe selection
plan and returns a callable resolver with `getCacheStats()`, `clearCache()` and
`dispose()` controls. The cache is resolver-local, least-recently-used and
bounded to `0..1024` entries; the default is `32` and `0` disables retention.

`useThemeSelector(selector)` subscribes to the selected value of the nearest
theme snapshot. Selectors should return a stable reference for unchanged
input; primitives are the simplest choice. The hook is intended for focused
token or derived-style reads when a component should not observe unrelated
theme changes.
