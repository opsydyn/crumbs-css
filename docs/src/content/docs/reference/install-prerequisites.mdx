## Required peer dependencies

- `react`
- `react-native`
- `metro`

Expo apps already satisfy the Metro side of this setup.

Effect is an implementation dependency installed with Crumbs. Applications do not add it as a peer dependency or supply Effect services/runners to use the styling and React APIs.

## Validated baseline

The current package contract is validated against:

- Expo SDK 56 / React Native 0.85
- Expo SDK 57 / React Native 0.86 with Crumbs 1.1.0
- Expo SDK 58 / React Native 0.88 with Crumbs 1.2.0; React / React DOM 19.3.1
- React 19.2 on retained SDK 56/57 lines

Crumbs 1.2.0 peers cover React Native `>=0.85 <0.87 || >=0.88 <0.89`; RN 0.87 is unqualified. Published 1.1.1 covers SDK 56/57 only. Crumbs tooling keeps Node `>=22.0.0`; SDK 56/57 tooling needs `>=22.13.0` and SDK 58 needs `^22.13.0 || ^24.3.0 || ^26.0.0 || >=27.0.0`. See [compatibility](../compatibility/) and the [1.2.0 release status](https://github.com/opsydyn/crumbs-css/blob/main/docs/releases/1.2.0.md) for the published compatibility release and its verification evidence.

## Required app setup

- Metro must be wrapped with `withNativeStyles`
- `.css.ts` authoring modules should import from `@opsydyn/crumbs-css/style`
- themed styles should be resolved before render

## Recommended environment

- Expo or React Native app using Metro
- clean Metro cache after configuration changes
- Storybook or Expo Dev Client for visual integration checks

## Known Expo Doctor caveat under Bun

If the consumer app is installed with Bun, `expo-doctor` can still report
duplicate Expo packages from Bun's `.bun/` symlink layout even when every
duplicate is the same version. Treat that warning as advisory until Expo Doctor
and Bun converge on the same install model.

## Current scope

This package is documented for React Native consumers first. Browser CSS runtime parity is out of scope.
