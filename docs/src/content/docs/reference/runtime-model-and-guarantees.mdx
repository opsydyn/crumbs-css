## Current runtime model

- `.css.ts` modules are transformed by Metro
- authoring helpers come from `@opsydyn/crumbs-css/style`
- themed style exports contain token references until runtime resolution
- `ThemeProvider` and `useThemedStyles` resolve those tokens against the active theme

## Runtime imports

Use `@opsydyn/crumbs-css/theme` for application runtime APIs. Its ESM and CommonJS emitted graphs depend externally only on React and exclude Node built-ins, authoring modules, esbuild, integration and CSS conversion code. The existing `dist/theme` alias shares this boundary. Runtime and tooling JavaScript build separately; declarations share one graph to preserve nominal token compatibility.

The root, `/style`, Metro plugin and transformer remain build-time entrypoints. Installed compiler dependencies are still required for authoring. The playground qualification inspects fresh production source maps for iOS, Android and web in workspace and packed modes; this does not establish device performance or native platform acceptance.

## Current guarantees

- React Native focused
- Metro-transform-based
- predictable recipe ordering
- explicit state selection for interactive styles
- stable diagnostic codes for tooling and CI

## Native structured values and variant maps

Legacy token ownership is the exact raw path of key segments. Identical paths can reuse a token name while themes retain independent value maps; different paths that sanitize to that name fail with `CRUMBS_CSS_THEME_TOKEN_COLLISION`. Registration is atomic and exposed metadata paths are frozen. Theme creation rejects relocated, invalid or unregistered leaves with `CRUMBS_CSS_INVALID_THEME_CONTRACT`. Registry checks apply within an authoring module instance/compiled graph. Namespace roots by package/design system; distinct cross-package/provider identities and wrong-provider detection remain M3 work. Existing non-colliding names stay unchanged.

Named `.css.ts` constants preserve finite primitives (including negative zero), undefined fields, dense arrays and plain/null-prototype data records. Ordinary tag-shaped records remain data. Unsupported functions, instances, cycles, accessors, symbols, non-finite values and other unsupported shapes fail with `CRUMBS_CSS_UNSUPPORTED_EXPORT` and file/export-path context. Default exports are unsupported. Import ordinary constants directly and omit them from style namespaces passed to theme hooks. Shared identity and descriptor/frozen status are outside the data contract. Legacy strings equal to registered style handles remain style references until the native IR provides distinct provenance.

Native token references are exact data DTOs with own enumerable `$$type: "crumbs.css.theme-token"` and `varName` fields. Names match `--crumbs-[A-Za-z0-9_-]+`. Constructors and resolution reject malformed tagged values with `CRUMBS_CSS_INVALID_THEME_TOKEN_REFERENCE`; the boolean guard returns false without executing reference accessors. Inherited fields, arrays and extra metadata fields are unsupported. JSON-decoded and null-prototype DTOs remain valid. Active theme lookup requires an own token value; missing or inherited values fail with `CRUMBS_CSS_MISSING_THEME_TOKEN`. Regenerate legacy/extended references when upgrading. These checks do not replace full theme/artifact schema validation.

Runtime resolution preserves supplied transform arrays and their order, native objects such as shadow offsets, scalar siblings and structured-value references. Ordered style arrays replace nested values as whole values. Only top-level token references are resolved; animated nodes are never evaluated by the resolver. Typed view/text/image inputs retain their primitive result types through direct resolvers, hooks, namespace resolution and style arrays.

Compiled `styleVariants` maps carry internal metadata while preserving their string keys and TypeScript variant keys. Object spread preserves this metadata. Unmarked legacy maps remain compatible when their shape is unambiguous; native structured-value shapes take precedence over ambiguous map shapes. JSON serialization drops map identity, so regenerate compiler artifacts when relying on native-property-like variant names.

The compiler captures static transform arrays and numeric `shadowOffset` / `textShadowOffset` before CSS serialization. Both emission modes preserve order and whole-value replacement, including imported bases, primitive helpers, variants and recipes. Transform entries accept one operation: finite numeric perspective/scales, finite numeric or percentage translations, deg/rad rotations/skews, or a 16-number matrix. Empty transforms are retained; offsets require finite numeric width and height.

Other structured authoring shapes, animated nodes and nested tokens fail with `CRUMBS_CSS_UNSUPPORTED_STRUCTURED_VALUE` even with permissive diagnostics. Direct primitive helpers also exclude animated transform nodes by type. Pass unsupported native values through React Native's runtime `style` prop. CSS strings retain the existing converter contract. Regenerate dependent artifacts together after upgrading; compiled-output checks do not establish native rendering or platform-specific shadow behavior. Nested token evaluation remains outside the current resolution contract.

## Required coverage and optional native capabilities

Package tests use durable consumer fixtures for themed styles, variant maps, recipes, web object emission, relative filenames and local theme imports. Tests and benchmarks admit the same required files; missing files/projects and directory impostors fail with the fixture path. An absent app cannot silently remove these checks.

The host Bun harness always measures five runtime operations and two warm compiler fixtures. Its JSON explicitly reports native/device performance as `not-run` with a reason. Batch-average quantiles are not individual-operation tails; these checks do not measure Hermes, React rendering, frame time or retained memory. Retained iOS simulator functional evidence is separate from these automated gates. Android native acceptance remains deferred and unqualified even when its production JavaScript export succeeds.

## What it does not guarantee

- browser CSS parity
- global cascade
- selector matching
- CSS-only responsive behavior
- CSS keyframe animations

## Recipe ordering guarantee

Resolved recipe arrays are ordered like this:

1. base
2. selected variants in author-defined order
3. matching compound variants in array order

Later entries override earlier ones using normal React Native style-array semantics.
