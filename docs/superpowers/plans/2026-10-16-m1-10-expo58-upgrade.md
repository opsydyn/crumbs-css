# M1.10 Expo SDK 58 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the user's retained native/inline execution choice. Steps use checkbox (`- [ ]`) syntax. This plan is proposed; no implementation is authorised by the assessment itself.

**Goal:** Qualify Crumbs for Expo SDK 58 / RN 0.88 without breaking the existing SDK 56/57 contracts, qualify optional Rust-transformer interoperability, then upgrade internal apps and prepare a release.

**Architecture:** Extend the existing pinned packed-consumer harness and three-SDK CI matrix. Keep the current Crumbs compiler/runtime contract and compose with Expo's upstream worker in Babel-control and Rust-enabled modes, applying only repairs backed by SDK 58 reproductions. Promote apps after library qualification; keep performance optimisations separate from compatibility claims.

**Tech Stack:** Observed Expo 58.0.11, template 58.0.20, React 19.3.0, RN 0.88.0, @expo/metro 58.0.0 / Metro 0.87.1, genuine Node 24.15.0, Bun 1.4.2, existing TypeScript 6.0.3. Resolve and pin all SDK-matched app packages at execution; reject prerelease or floating qualification inputs.

**Spec:** [Impact assessment and upgrade design](../../assessments/2026-10-16-m1-10-expo58-assessment.md).

## Global Constraints

- Preserve SDK 56 / RN 0.85 and SDK 57 / RN 0.86, existing imports, emitted payload versions and runtime APIs.
- Proposed RN peer after success: `>=0.85 <0.87 || >=0.88 <0.89`. RN 0.87 remains unqualified; React stays `>=19 <20`. Library Node >=22.0.0 is unchanged; SDK 58 tooling must satisfy both Expo/RN engine constraints recorded in the assessment.
- SDK 58 retains Babel as the control and explicitly targets Noxcturnal interoperability through Expo's worker. No Rust rewrite of Crumbs, native Expo UI backend, hinge API, SwiftPM migration, agent CLI adoption or variable-font token expansion in this batch. Crumbs adds no direct Rust binary/package dependency.
- No forced/legacy peer resolution, linked packed consumers, replaced baselines or inherited release exceptions. Native and device performance claims require their own evidence. Physical hardware/spoken readers stay deferred.
- Preserve the existing SDK 57 candidate command/default and `--sdk=56` installed-mode behavior. New selectors are explicit and pinned in CI.
- Retain the current dirty primary checkout, untracked `.superpowers/` and Storybook iOS data. Use owned staged native projects and isolated ports; no global simulator/AVD/cache cleanup.
- Three coherent implementation slices, one commit after each; recommend the next numbered slice after each commit. No publication until separately authorised.
