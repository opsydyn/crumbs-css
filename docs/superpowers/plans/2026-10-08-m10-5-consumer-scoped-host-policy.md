## Review Focus

Each case below is exercised in Steps 2 or 4, and inspected in the final whole-candidate review:

1. Advisory raw data or environment is missing/invalid while the stored outcome says qualified: both report and publisher reject.
2. Only a report role, summary or boolean is changed, or a policy role is edited and all hashes resealed: the approved partition and rederived result still control admission.
3. Baseline evidence is edited without changing its median: approved evidence hashes still reject the edit; arithmetic alone cannot validate provenance.
4. Publisher has no local `dist`, or has a different local build: transferred tarball/artifact identities remain authoritative, without bypassing source/policy checks.
5. Current-policy reports and legacy formats are mixed, or bindings drift during collection: reject rather than silently translate evidence or select an environment override.

## File Structure and Interfaces

Create `packages/css/bench/release-host-budget-policy-contract.ts` for private Effect schemas/codecs and exported types; create `scripts/release-host-budget-policy.json` for the accepted policy data. Extend `scripts/release-host-budget-policy.ts` for fixed-role validation, binding capture and evaluation. Update the collector, report validator, CLI, manifest codec and publisher together; retain their existing distinct responsibilities.

- `HostBudgetPolicyBinding = Readonly<{policyId:string; policySha256:string; registrySha256:string}>`.
- `HostBudgetPolicy = {formatVersion:1; policyId:string; registrySha256:string; metrics:readonly {id:string; selector:string; enforcement:"blocking"|"advisory"}[]; baselineFiles:readonly {path:string; sha256:string}[]}`. Initial `metrics` follow the approved snapshot order; initial `baselineFiles` use the [immutable evidence inventory](../../evidence/2026-10-08-m10-5-consumer-policy-plan/baseline-files.json), derived from review commit `60499bf`. File hashes reinforce the approved evidence-preservation requirement; they do not change a baseline.
- The contract module exports `releaseHostBudgetPolicyCodec`, `hostBudgetPolicyBindingCodec` and `HostBudgetPolicyBindingSchema`, following `makeDataCodec`. Its schemas require finite versions, SHA-256s, supported roles and safe relative baseline paths. Policy validation additionally pins the policy ID, registry digest, all selectors, closed set, explicit ten advisory IDs and baseline inventory; role selection must not depend on a mutable registry domain or caller environment.
- `loadHostBudgetPolicy(repositoryRoot:string):HostBudgetPolicy` decodes the fixed policy path and validates the pinned contract, registry bytes and baseline inventory. `captureHostBudgetPolicyBinding(repositoryRoot:string):HostBudgetPolicyBinding` uses that validated policy and hashes raw bytes; invalid input throws. `verifyHostBudgetPolicyBinding(binding:unknown,repositoryRoot:string):readonly string[]` returns diagnostics for missing/malformed/mismatching bindings instead of trusting report values.
- `verifyReleaseHostBudgetRegistry(registry:BudgetRegistry,policy:HostBudgetPolicy):readonly string[]` retains existing recorded/approved-row checks and enforces the exact contract snapshot. `evaluateReleaseHostBudgetRows(rows:readonly {id:string;result:string}[],policy:HostBudgetPolicy):ReleaseHostBudgetEvaluation` validates the pinned policy before applying roles.
- `HostBudgetRoleSummary = Readonly<{passIds:readonly string[];failIds:readonly string[];incompleteIds:readonly string[]}>`. `ReleaseHostBudgetEvaluation = Readonly<{releasePolicyQualified:boolean;blockers:readonly string[];blocking:HostBudgetRoleSummary;advisory:HostBudgetRoleSummary}>`. Unsupported statuses belong in `incompleteIds` and blockers, never the accepted advisory-failure category.
- Keep the 21 rows' existing shape/arithmetic. Comparison format 3 adds `policy:HostBudgetPolicyBinding` plus the four evaluation fields above; validate stored evaluation fields against independent derivation. Input identity adds `policyBefore` and `policyAfter`, each the same binding. Manifest format 2 adds `policy` with that binding; retain every existing manifest field. Reject comparison format 2 and manifest format 1 for new admission.
- `verifyReleaseHostBudgetReport` returns the evaluation fields, existing optional `sourceRevision`/`sourceDigest`, and optional `policy` when available. Replace private `.qualified` budget-result consumers with `.releasePolicyQualified`; do not keep an ambiguous alias. `verifyReleaseQualificationBundle(...).valid` remains an integrity/admission result and its public tooling signature otherwise stays unchanged.
