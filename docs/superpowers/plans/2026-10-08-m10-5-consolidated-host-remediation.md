# M10.5 Consolidated Host-Budget Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user selected inline execution; do not reopen execution-method selection or delegate implementation tasks.

**Goal:** Attempt to remediate the nine binding host-budget failures in one API-preserving batch, admitting production changes only when all 21 unchanged host comparisons and behavioural checks pass.

**Architecture:** Share runtime admission/traversal mechanics while preserving boundary-specific semantics. Reuse only fully verified compiled text in a bounded resource-free memo, then evaluate authoring and emit native output anew. Independent base-source controls and early graph rejection prevent an incomplete candidate becoming shipping code.

**Tech Stack:** Existing Bun/TypeScript, React, Vanilla Extract integration 8.0.10, esbuild 0.27.7 and tsdown 0.21.10; genuine Node 22.0.0 and Node 24.15.0. No dependency changes.

**Spec:** [Approved consolidated design](../specs/2026-10-08-m10-5-consolidated-host-remediation-design.md).

## Global Constraints

- Preserve every public export, path, type relationship, synchronous capability, diagnostic, descriptor version, cache guarantee and supported platform; add no public option, dependency or subpath.
- Preserve compatibility/focused binding identity, React contexts, symbol registries, validation/registration timing, lazy branches and ordering. Do not hide implementations behind dynamic/external loads.
- Keep all 21 IDs/selectors and all approved baselines, limits and environment comparisons unchanged. Read exact limits from `packages/css/bench/budgets.json`; graph maxima are 17,271/17,641 B for core and 44,017/44,764 B for compatibility; warm full transform is at most 6.514 ms and 15% regression.
- Memo limits: 16 entries globally, 8 MiB aggregate UTF-8 source-plus-serialised-metadata payload, 1 MiB per entry. No contexts, watchers, timers or owned worker resources. These are payload bounds, not heap guarantees.
- One production implementation batch and final commit; no per-task production commits or partial admissions. On an unsolved failure retain one reproducible evidence result and remove the complete candidate from shipping source.
- Execute in the existing managed `crumbs-main-merge/crumbs-css` worktree. Preserve its unrelated untracked files and the primary checkout's edits. Never mutate shared installed dependencies; isolated copies own mutation tests. Any temporary dependency links must be inventoried and restored.
- Physical-device and spoken-reader checks remain deferred; Simulator/emulator software checks are permitted. No push, publication or runner provisioning in this batch.

## Review Focus

1. Proxy arrays: preserve own-key/descriptor trap sequence and symbol-versus-shape error precedence, not merely the eventual error (Tasks 1–2).
2. Resolution alternatives: an added higher-priority file/package or changed bundled installed source must invalidate reuse and Metro's outer cache (Tasks 3–5).
3. Authoring execution: a reused compilation must still execute ambient reads/side effects, with no cached evaluation failure or native result (Task 4).
4. Concurrent edit/restore: an older completion must not overwrite a newer memo entry or return stale output; independent project roots must never share entries (Tasks 3–5).
5. Qualification identity: a passing helper or stale report cannot replace the complete current-source transform/graph/host run; rejected candidate source must not remain shipping (Tasks 1 and 6).
