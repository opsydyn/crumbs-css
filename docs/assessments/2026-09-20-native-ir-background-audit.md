# M2.2ay experimental background audit

The installed React Native 0.83 ViewStyle contract exposes four experimental background fields. They are inherited by `TextStyle` and absent from `ImageStyle`, so any future static IR uses the `view`/`text` primitive domain. The fields are separately preprocessed by React Native and must not share a recursive object carrier.

| Field | Installed value family | Array-path processor behaviour | Static IR decision |
| --- | --- | --- | --- |
| `experimental_backgroundRepeat` | `ReadonlyArray<{ x: repeat \| space \| round \| no-repeat; y: ... }>` or string | Array values pass through; CSS strings parse `repeat-x`, `repeat-y`, one keyword or two keywords into canonical `{ x, y }`. | First candidate for M2.2az: exact two-key closed record, literal domain, no nested semantics. |
| `experimental_backgroundSize` | `ReadonlyArray<{ x: string \| number; y: string \| number } \| 'cover' \| 'contain'>` or string | Array values pass through; CSS strings accept non-negative `px`, `%`, `auto`, `cover` and `contain`, with one-value `y: 'auto'` expansion. | Separate M2.2ba contract: exact keyword or `{ x, y }` record with a finite/non-negative length-percentage domain. |
| `experimental_backgroundPosition` | `ReadonlyArray` of four exact key unions (`top/left`, `top/right`, `bottom/left`, `bottom/right`) with `string \| number` values or string | Array values pass through; CSS strings parse one to four keyword/length-percentage forms and canonicalise them to one of the four records. | Separate M2.2bb contract: exact union, canonical key shape and finite zero/`px`/`%` values; broad strings and tokens remain runtime. |
| `experimental_backgroundImage` | `ReadonlyArray<LinearGradientValue \| RadialGradientValue>` or string | Array values validate colour stops and linear direction/radial shape-size syntax in the JS processor, apply defaults and return parsed gradients; native CSS parsing can bypass this processor. | Last: M2.2bc must define separate linear/radial gradient records, colour-stop transition hints, colour domains, direction/angle units, radial size/position and minimum list semantics before capture. |

The installed declarations are intentionally broad. Linear gradients use `direction?: string` and colour stops with `ColorValue | null` plus arbitrary string positions. Radial gradients combine shape, extent or `{ x, y }` size, a four-shape position union and the same colour-stop form. `ColorValue` includes opaque symbol-backed platform colours, and transition hints use `color: null` with exactly one percentage or numeric position. Those values cannot enter a static IR without a separate token/platform policy.

The array processors for size, position and repeat return authored arrays without validating or normalising their entries. The image processor has more semantics: it rejects invalid colour stops, applies default linear direction and radial shape/size/position, parses angle units (`deg`, `grad`, `rad`, `turn`), and accepts CSS strings with a richer grammar than the object declarations. The `nativeCSSParsing` feature flag can bypass all JavaScript processors, so static admission must preserve the raw native contract and cannot claim cross-platform rendering parity.

Crumbs already preserves these arrays during runtime theme resolution through `NATIVE_ARRAY_VALUE_PROPS`, but the CSS-to-React-Native allowlist has no experimental background entries. String forms therefore remain runtime-only compatibility values. Any future marked static capture must remove the field before CSS conversion and retain the existing `CRUMBS_CSS_UNSUPPORTED_STRUCTURED_VALUE` boundary for malformed or dynamic entries.

The migration order is deliberately repeat → size → position → image. Repeat can be qualified as a small closed literal record. Size and position need independent length/percentage and canonical-key contracts. Gradient images remain last because nested colour stops, transition hints, parser defaults, native CSS parsing and platform support require a native-device acceptance slice. This audit changes no public API, structured IR or native ABI.
