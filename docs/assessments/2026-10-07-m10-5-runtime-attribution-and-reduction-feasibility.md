## Decision

Do not make another production runtime or transformer change from this evidence. The current host run confirms the initialization, warm-transform and theme-graph failures. Source-map attribution identifies where emitted theme/core code comes from, while the retained profile and phase studies explain the measurement limits. The already-tested static extraction and minification candidates do not meet the unchanged gates. **M10.5 remains open.**

The current clean-host report records 11 passes, nine failures and one incomplete Expo/Metro comparison against the current tracked source. Its content digest is db9a02ecd57c1c0c11f96ea19640fb975f447ae03bf52117ef2dcc3c349f9894; the measured source and 145 built artifacts were stable throughout collection. The current theme-runtime.ts and transformer.ts hashes match their benchmark input receipts.

## Warm-transform attribution

The current exact-workload host median is 9.754 ms against a 5.664 ms baseline and an unchanged 6.514 ms ceiling. Earlier exact-fixture phase studies attributed about 5.75–5.91 ms to Vanilla Extract's esbuild integration build and about 0.9–1.5 ms to debug-ID transformation. A transformSync candidate preserved generated module bodies, but its full-transform ranges overlapped the baseline and its consumer median was slightly slower. A short-ID candidate improved timings but changed development output and failed parity. Neither is an admissible production change.

Those instrumented phase values diagnose the earlier measured workload; they do not explain the difference between that run and the current 9.754 ms host result. The current host budget remains the authoritative gate. See the [phase attribution](2026-10-04-m10-5-phase-attribution.md), [compile subphase A/B](2026-10-04-m10-5-compile-subphase-ab.md) and [warm-transform candidate review](2026-10-04-m10-5-warm-transform-cost.md).

## Graph-reduction feasibility

The retained static-boundary candidate preserved current exports, validation, recursive resolution and binding identity, but increased each theme graph by 295–515 bytes. Its paired import-plus-first-use results showed no qualifying improvement. The package-wide minified output also remained roughly twice the approved theme graph limits and continued to fail startup gates. Both are rejected for production under the current API and budget policy. The full measurements and archived candidate are in the [runtime-boundary assessment](2026-10-06-m10-5-runtime-boundary.md).

No public API, production dependency, baseline, threshold or enforcement rule changes in this slice. The Expo/Hermes consumer matrix remains software-context evidence and does not replace the binding host gates. Physical-device work remains deferred.
