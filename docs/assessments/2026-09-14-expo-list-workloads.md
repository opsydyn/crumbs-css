# Expo list lifecycle workloads — 2026-09-14

Approved M1.5a under ADR D6/D12, based on `7e0e879`. The [Expo playground](../../apps/playground/README.md#repeatable-list-lifecycle-workloads) now exposes static/themed list mount, unchanged-theme rerender, local-theme switch and unmount workloads. Five cycles and 25/100/1,000 requested rows make setup repeatable; each run records its own identity and actual observations. Parent M1.5 remains open for recipe/scope/scroll/orientation/font-scale/retained-memory workloads. This is a functional measurement foundation, not calibrated device performance.

## Scenario and observation contract

The **Measure** journey consumes public Crumbs `dist` exports. The themed scenario uses one `useThemedStyles` hook over a stable module per list; the static scenario uses a hoisted native StyleSheet with corresponding light row geometry/values. It probes module memo reuse, not per-row hooks or recipe-result caching. Both lists use FlatList initial/batch size 10 and window size 5. Each cycle mounts under a stable light theme, rerenders, changes the local provider to dark, then unmounts. Timers request a 250 ms dwell; actual scheduling/virtualization and background throttling can extend it.

A child layout-effect observes the resolved style-module object reference. The unchanged-theme rerender must reuse the same themed object; the theme switch must replace it; static objects remain stable. These observations do not count underlying schema calls, token traversals or memory allocation. List/row layout-effects count actual mounts and cleanups, including effects for virtualized rows. Requested data length differs from mounted/visible row count. Balanced effects do not prove leak freedom, GC reclamation or correct rendering on a native device.

Each receipt contains mode/version/source/run identity, timestamps, platform/development/native-version/profiler availability, configuration, all 20 ordered step observations, lifecycle counts and raw Profiler callbacks when available. Missing/duplicate/out-of-order steps, impossible counts and unexpected style identities cannot pass the verification summary. The completion UI distinguishes verified sequences from ones needing review. Controls prevent overlapping scenario runs; navigating away discards an unfinished run and clears its pending timer. Instrumented development Strict Mode can replay effects and must be treated explicitly rather than assuming one effect equals one native mount.

`requestToLayoutEffectMs` includes JavaScript scheduling and commit delay; it is not render CPU, native layout, paint or visual readiness. Profiler actual/base durations describe React render work within the list subtree when profiling is enabled. Virtualized row updates may produce multiple callbacks for one step; unmounts do not have a Profiler render callback in this boundary. Production profiling can be disabled and is reported unavailable. Measurements include instrumentation and uncontrolled host conditions; no tail-latency, calibrated budget, device/frame/memory or optimization claim is made.

The retained static/themed runs at all three sizes each have five complete cycles, expected style identities and balanced lifecycle counts. Their 30 total cycles / 120 ordered step observations and optional development Profiler data are functional web evidence. [Live summary](../evidence/2026-09-14-expo-list-workloads/live-summary.json) identifies each raw receipt. A leave-and-return check also resets idle controls without admitting an unfinished report. Some host tooling was active during these runs; the raw timings are not an idle-host comparison or a release/native performance baseline. [Static completion screenshot](../evidence/2026-09-14-expo-list-workloads/web-static-complete.png) was visually inspected; it is a web viewport, not native visual acceptance.
