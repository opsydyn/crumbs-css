# M1.5d: actual React Native orientation/font-scale context workloads

Measure now includes orientation and font-scale context workloads. Each run records a baseline from React Native useWindowDimensions and executes five baseline → rerender → change → restore cycles. The probe uses a stable module with public useThemedStyles under a constant light ThemeProvider, through the real Metro transform. No dimensions/fontScale values are injected into React Native.

Orientation changes require the opposite width/height orientation while retaining density/font-scale, followed by the original baseline dimensions. Font-scale changes require a different actual fontScale while retaining dimensions/density, followed by restoration of the baseline. The 0.01-point comparison tolerance permits numeric rounding. A resize cannot substitute for font scaling. Each request has a thirty-second deadline; explicit user cancellation and navigation produce terminal incomplete reports. Invalid, stale, duplicate or late observations cannot complete a sequence.

Child layout effects record the actual hook context, style-module object identity, resolved text color/font size and commit timestamp. The recorder retains accepted ordered observations separately from all probe commits. Complete context sequencing and reference verification are separate flags: all context changes under the same module/theme should retain the themed-hook object, because that hook currently memoizes by module/theme identity. This workload does not introduce responsive conditions or promise context-driven style changes. Logical fontSize remains 16; OS font scaling is a rendering concern, not a change to the authored logical size.

Reports retain source/package identity, platform/development state, baseline/plan, observations, all probe commits and raw Profiler callbacks. The Profiler step label uses the render's captured step, rather than reading the recorder after child layout effects advance it. Timings include instrumentation, scheduling and uncontrolled host load; they do not measure frame/paint latency or calibrated performance.

## Qualification and limits

[Evidence](../evidence/2026-09-14-expo-context-workloads/qualification.json) retains two actual Expo development web orientation runs starting in opposite orientations: ten cycles/forty ordered steps, each with verified references. A font-scale run observes real resizes while fontScale stays 1, then times out after two accepted baseline/rerender steps; this is negative web evidence, not native font-scale acceptance. User/navigation cancellation and the final screenshot are retained. Synthetic native-like font-scale values occur only in recorder unit tests and are explicitly distinct from live receipts.

Package checks, workspace Expo typecheck and three JavaScript maps, isolated local-tarball npm Expo typecheck and three maps, Storybook types and twenty-page docs build pass. Both consumers' runtime map guards deny compiler/Node/Effect sources. No dependency or library runtime API changes are introduced. The original release version edits remain excluded; no push/publication.

M1.5d closes the workload/instrumentation foundation.
