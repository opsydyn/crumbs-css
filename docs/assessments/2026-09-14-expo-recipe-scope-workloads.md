# M1.5b: repeatable Expo recipe and scope workloads

The Measure journey now includes a recipe/scope workload alongside the existing list workload. Five cycles each execute mount, same-context rerender, selection, repeated selection, parent-theme switch, nested-theme switch and unmount. The two probes use public authoring, ThemeProvider, useThemedStyles and resolveRecipeStyle APIs through the actual Metro transform.

The recipe exercises two default variants, explicit selected/large variants and a compound border-width override. An independent literal oracle checks light/dark accent colors, opacity, padding and border width. Native lowering expands padding and border shorthands; observations require all four edges to agree before recording their common value. Each scope records actual hook object identities and recipe-array freshness. Same-theme rerenders/selections retain hook objects, parent changes replace only the parent object's reference, and nested changes replace only the nested object's reference. Recipe arrays are freshly allocated; this is observation of the current uncached implementation, not cache or performance acceptance.

Child layout effects collect style and reference receipts and actual mount/cleanup counts. The parent records ordered commit observations and checks missing/duplicate steps, finite nonnegative delays, expected styles, references and lifecycle balance. The five-cycle workload requires ten probe mounts and ten cleanups. The report retains identity, platform, development flag, raw observations and React Profiler callbacks. Navigating away cancels the pending timer rather than producing a completed receipt.

## Verification and evidence

See [retained evidence](../evidence/2026-09-14-expo-recipe-scope-workloads/qualification.json). Two final-source development web runs cover ten cycles and seventy ordered steps, with all style/reference/lifecycle flags true. Earlier receipts are retained as diagnostic evidence: web-run-1 exposed an observer reading shorthand properties instead of lowered edges; web-run-2 and web-run-3 passed the corrected observer before the empty-string JSX warning was repaired. They are not final-source acceptance receipts. The final screenshot was visually inspected. Returning to the existing themed 100-row list workload also verified all five cycles and twenty steps.

The package checks, workspace Expo typecheck and three production JavaScript exports, isolated local-tarball npm Expo typecheck and three exports, Storybook typecheck, and twenty-page documentation build pass. The runtime map guard rejects compiler/Node/Effect sources; both consumers' three maps pass. Negative tests cover missing receipts, incorrect scope values/references, incomplete cleanup, nonfinite timing, invalid cycle counts and an empty protocol.

No new dependency or runtime library API is introduced. The ADR remains proposed. M1.5b is a functional workload foundation; parent M1.5 remains open. Request-to-layout-effect includes scheduling and uncontrolled host load, not render CPU or visual readiness. Profiler receipts do not measure JS/UI frames. No release-device performance, scrolling, orientation/font-scale, retained-memory/leak, thermal or calibrated-budget qualification is claimed. iOS native acceptance is not rerun and native Android stays last. M1.3b's external-theme decoder remains absent/unqualified. No publication or push; the preexisting release version edits remain excluded.
