# M10.5 compiler-identity prerequisite

Date: 2026-10-08. Disposition: **identity premise not established; no production memo admission**.

The approved compiler-identity investigation found an executable counterexample to the proposed shortcut of checking loaded module namespaces and post-load disk hashes. esbuild 0.27.7 keeps its native service in private mutable state: unchanged JavaScript bindings can use an existing process or start a new executable. The [retained packet](../evidence/2026-10-08-m10-5-compiler-identity-prerequisite/README.md) reproduces this under genuine Node 22.0.0, Node 24.15.0 and Bun 1.4.2.

Each owned process first compiles with the original native executable, then atomically replaces only its private copy with an unusable executable. Confirmation still compiles through the running original service. At that point the probe captures module instances, shallow export descriptors, compile/build/stop functions, environment hash, entry bytes and current executable bytes. Calling the public esbuild `stop()` changes none of those recorded predicates. Independently fresh compilation then fails with `The service was stopped`; returning previously compiled text would hide that failure. Restoring the executable restores the original source hash and full watch-file list in all three runtimes. No memo was implemented: the replay result is hypothetical and explicitly marked unexecuted.

This demonstrates why a disk image observed after compilation cannot prove the executing service's origin. A guard that establishes origin before startup could reject this particular case; it would still need complete lifetime/restart and mutable-input proof. No such complete guard has been established within the approved resource and API constraints. A private Node handle probe observes a child process during compilation, whereas the Bun probe returns no handles. Those observations do not prove that all other guards are impossible, and are not a supported production mechanism. The broader Babel/parser/resolver identity inventory stopped at this failed prerequisite.

The [approved design](../superpowers/specs/2026-10-08-m10-5-compiled-text-identity-design.md) states: “If this premise fails, reject this approach before integrating a memo.” Its implementation-plan handoff is conditional on the premise passing. Consequently this slice retains fresh compilation and records rejection of integration based on the tested predicates. It does not substitute an undefined proof task into a production plan or claim that every safe memo is infeasible.

Fresh before/after receipts verify all 696 shipping files against the prior full source identity, all 149 emitted artifacts, the unchanged numerical registry and policy, 18 shared compiler-package files, original managed dependency links and the primary checkout's dirty files/status. Only copied integration/esbuild/native packages in an owned temporary installation were mutated; the owned executable was restored and services stopped. The offline packet verifier checks report semantics, integrity and six semantic rejection controls. No package/site build, native/export check, timing run or complete host suite was repeated for this documentation-only disposition.

M10.5 remains open.
