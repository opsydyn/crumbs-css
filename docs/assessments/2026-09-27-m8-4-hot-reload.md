# M8.4 Metro hot reload and dependency invalidation

The live [Metro receipt](../evidence/2026-09-27-m8-4-hot-reload/metro-incremental.json) exercises the Expo 56.0.4 / Metro 0.84.4 / React Native 0.85.3 development bundle on iOS from a warm Metro server.

The dependency controls edit a plain token, a nested `.css.ts` module, and shared workspace theme configuration. In each bundle response the newly compiled value appears and the prior value is absent: `30001 → 30002`, `31001 → 31003`, and `32001 → 32004`. Five retained direct style edits also produce the new padding value and remove the preceding value.

The config control starts with one cache clear, then restarts Metro three times without clearing it. The same edited style compiles with `strictDiagnostics: false` and includes padding `30901`; after restart with strict diagnostics enabled, Metro returns the expected `CRUMBS_CSS_DROPPED_DECLARATION` error; returning to permissive mode reproduces the exact original bundle hash. This proves the configured transform result follows the changed setting and that restoration returns the original output.

The runner restores all edited fixtures and records matching original/restored source hashes. Its receipt records the M8.3 base revision and that the source tree was dirty during this M8.4 run. The evidence is limited to the recorded macOS host and iOS development-bundle endpoint. It does not qualify Expo-client Fast Refresh visuals, native rendering, Android/device behavior, or performance budgets. Android and device acceptance remain parked.
