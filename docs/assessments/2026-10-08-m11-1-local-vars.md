## Behaviour and boundaries

`createVar` and `fallbackVar` author domain-typed native scalar inputs through `/style`. The opt-in `/theme/vars` entry exports `assignVars`, `resolveAssignedStyles` and `useAssignedStyles`, with six public types. Each component owns an immutable complete assignment snapshot. Subset shapes remove omitted assignments; an empty shape clears them. Only absence advances a fallback, so zero remains present. A reached public typed theme terminal uses the existing provider/scoped store; a literal or populated local branch needs no provider.

The compiler captures local values before CSS conversion, applies native shorthand/last-write composition and emits portable frozen local plan v1 data with dependency metadata. Unresolved plans never reach `StyleSheet.create`; existing theme resolvers direct callers to `/theme/vars`, including cached nested inputs. Primitive types remain intact until resolution. Local operands remain excluded from recipes, Sprinkles, conditions, expressions and structured values; supported static structured values may coexist with local scalar inputs.

Admission descriptor-reads own plain/null-prototype data and freezes copies; mutable decoded inputs are revalidated. Weak identity caches handle immutable inputs, and the bounded per-selector state reuses unaffected rows or the complete map after unused changes. All bindings and unused fallback literals are validated. Native property restrictions still apply after domain admission.

Existing payload versions and compatibility exports/binding relationships remain intact. Existing runtime graphs do not import local assignment/resolution merely by importing their entrypoints. Effect remains pinned at `4.0.0-rc.115` at tooling/schema boundaries; the new ordinary runtime graph has React as its only external and adds no dependency.
