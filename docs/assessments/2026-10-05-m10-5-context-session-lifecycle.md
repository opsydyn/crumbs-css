## Ownership and decisions

One session serialises all compilation and native evaluation. Caller requests are copied at admission; returned source/input/watch receipts and public snapshots are detached immutable values. Resource effects interpret the pure admission policy; its success state is committed only after native evaluation succeeds. Every hit rebuilds; neither errors nor last-good output are cached.

Owned-resource accounting includes retained handles, creations in progress, disposal in progress and failed-disposal quarantine. Eviction disposal completes before replacement creation. Failed disposal withdraws handles from admission, records the failure, disables retention and keeps unresolved ownership counted; remaining handles are drained. Later calls use fresh compilation. Quarantined handles are not silently retried or claimed disposed. `close()` retains one promise and completion outcome, drains previously admitted requests, rejects new work, clears admission state and reports cleanup errors. A failed close may leave explicitly counted quarantine until process exit; it is not successful cleanup.

Idle expiration drains only the current generation, permitting later reopening. One unreferenced owner timer is armed after queued/active work drains. Arrival cancels its deadline; token and generation checks guard stale callbacks. A request arriving during disposal waits behind the same gate. Direct tooling callers must await close in finally; no global esbuild stop, signals or Metro worker-bootstrap replacement is installed.

Configuration receipts are checked before/after retained builds, actual metafile input paths must pass the declared-domain validator, and finite input roots are byte-hashed before/after compilation. Observed configuration/project changes drain the old generation and select fresh for the transition. Loaded implementation/package-info changes disable retention and record a restart requirement; fresh compilation in that same process does not refresh already loaded JavaScript or integration package caches. Entry-buffer conflicts, unknown domains and observed source instability select fresh. The module owner fixes its loaded-artifact inventory at initial admission. A subsequent project must use that same compiler inventory; introducing another declared implementation requires restart and disables retention rather than assuming its code was loaded. Projects with the same compiler inventory can drain/reopen normally. Entire-root byte checks are conservative candidate overhead to include in later performance timing. They provide no atomic filesystem snapshot and do not prove which bytes an overlapping build read.

## Real compiler adapter

The backend resolves esbuild through installed Vanilla Extract integration and asserts exact versions 0.27.7/8.0.10. Fresh mode calls the existing integration compile API with a current receipt collector. Retained mode supplies the same compile option surface and integration's exported file-scope plugin to an owned esbuild context. Each rebuild installs a new capture slot, rejects absent/error receipts and detaches that slot and its request reference in finally. Supported caller receipt collectors route through that current slot instead of installing their closures in a persistent context. Direct close uses only owned context disposal. No dependency export is patched and no compiler package is added.
