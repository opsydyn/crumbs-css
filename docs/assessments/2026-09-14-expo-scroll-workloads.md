# M1.5c: repeatable Expo list scrolling

Measure now offers static and themed programmatic scrolling at 25, 100 and 1,000 requested rows. Each run performs five middle → end → top cycles using fixed 80-point rows in a 240-point viewport. The themed path uses the public ThemeProvider and stable-module useThemedStyles hook through Metro; the static path uses React Native StyleSheet. Geometry overrides keep the two paths comparable without changing the existing list or recipe/scope scenarios.

The plan independently specifies each target offset and expected visible row indices. FlatList's real onScroll callback records offset, viewport and content geometry; onViewableItemsChanged records sorted viewable indices. A command alone cannot complete a step. Both callbacks must be fresh for that command, all geometry/indices must match, and at least 100ms must pass after the latest scroll/viewability event before acceptance. Two-point geometry tolerance permits platform rounding. A three-second deadline bounds initial layout/content readiness and every command. The polling interval is 50ms; it is a functional observation protocol, not a frame sampler.

A recorder admits each ordered step once and makes completed/cancelled/timed-out states terminal. Explicit Cancel retains a JSON report with partial observations and reason. Navigation clears timers and emits a cancellation report to the development console; it does not claim completion. Reports include source/package identity, environment, independent plan, raw callback history, accepted observations, and React Profiler callbacks where available. Negative tests reject stale or nonfinite samples, incorrect geometry/indices, duplicate advancement, late matching callbacks, and incomplete/deadline/cancelled sequences.

## Qualification

[Retained evidence](../evidence/2026-09-14-expo-scroll-workloads/qualification.json) includes all six final-source development web cases, five cycles each: thirty cycles/ninety admitted destinations. User cancellation and navigation cancellation retain incomplete reports. The initial diagnostic run is retained separately; final runs include tightened deadline admission. A final screenshot is visually reviewed for readable controls/status/report.

Package verification passes 276 tests with 11,604 assertions across 42 files. Workspace and freshly packed isolated npm Expo consumers typecheck and export web/iOS/Android JavaScript, with three runtime maps each passing compiler/Node/Effect denial. Storybook typechecking and the twenty-page docs build pass. No dependency or library runtime/API changes are introduced. Preexisting release version edits remain excluded; no push or publication.

These receipts measure programmatic fixed-geometry callbacks, not touch/fling physics or painted visibility. RN viewability callbacks report the framework's viewability decision; they are not visual paint evidence. Timings include scheduling, instrumentation and uncontrolled host load; React Profiler data are not JS/UI frame or calibrated performance measurements. No physical/release Hermes device, retained-memory/leak, orientation/font-scale or thermal qualification occurs. Native iOS is not rerun; native Android stays last. Parent M1.5 remains open, M1.3b remains absent/unqualified and the ADR stays proposed.
